# PROJECT_CONTEXT

> 이 파일은 사이트를 만들 때 AI가 가장 먼저 읽는 프로젝트 설명서입니다.
> 기획 문서에서 구현에 필요한 내용만 모아 두고, 수정할 때마다 최신 상태로 맞춥니다.

## AI 작성 규칙
1. 사용자가 준 문서와 답변에 있는 내용만 씁니다. 없는 내용을 지어내지 않습니다.
2. 비어 있는 항목은 질문 기능으로 물어봅니다. 선택지와 추천안을 함께 보여 줍니다.
3. 사용자가 '미정'이라고 답한 항목은 [미정]으로 표시하고, 그 항목이 필요한 제작 단계에서 다시 묻습니다.
4. 각 내용 옆에 가져온 문서를 (출처: 파일명) 형태로 적습니다.
5. 분석 과정, 검토 메모, 선택하지 않은 후보처럼 구현에 영향이 없는 내용은 넣지 않습니다.
6. 화면이나 규칙이 바뀌면 이 파일에도 바로 반영합니다.

## 1. 프로젝트 개요
- 사이트 이름: LOWCORE (로우코어) (출처: 01)
- 한 줄 설명: 음악·영상 작업용 모니터 스피커 브랜드의 단일 상품 사이트. 크기별 2종(5인치 / 8인치) (출처: 01)
- 모델명: 5인치 `LC-5-105`, 8인치 `LC-8-112`. 사이트에서 모델을 부를 때는 이 이름을 씀 (출처: 요청)
- 메인카피: 들리지 않던 저음까지, 작업의 기준이 되는 스피커 LOWCORE. (출처: 01)
- 서브카피: 같은 트랙을 PC 스피커와 LOWCORE로 번갈아 들으며, 저음의 차이를 직접 확인해 보세요. (출처: 01)
- 사이트 목적: 방문자가 PC 스피커와의 저음 차이를 직접 들어 보고, 소리가 달라지는 이유를 이해하도록 돕는다. (출처: 01)
- 가장 중요한 행동: 비교 체험 재생 — 같은 트랙을 PC 스피커와 방문자가 고른 LOWCORE 모델로 번갈아 듣기 (출처: 01)
- 보조 행동: 제품 상세 보기 → 구매. 구매는 구매 버튼까지만 만들고 결제 화면은 만들지 않음 (출처: 01)
- 피해야 할 방향: 저음 과장·소비자용 느낌 / 자동 재생·갑작스러운 큰 소리 / 구매 강요·과한 할인 강조 (출처: 01)

### 3-3. S02 비교 체험 구성과 동작
- 섹션 맨 위: 헤드폰 착용 권장 안내 상자 (출처: 02, 04)
- 안내 문구: "모델을 선택한 뒤 재생 버튼을 누르면 음원이 재생됩니다." (출처: 02, 04)
- 이미지 3개(B07 PC 스피커, B08 5인치, B09 8인치)를 같은 크기로 가로 나란히 배치 (출처: 04, 05 R2)
- 이미지 라벨: 'PC 스피커' / 'LC-5-105' / 'LC-8-112' (출처: 요청)
- 자동 재생 없음. 이미지를 누르면 선택만 되고, B10을 눌러야 재생됨 (출처: 02, 04)
- 선택된 이미지: 테두리로 선택 표시, 조금 확대. 나머지 두 이미지는 블러 처리 (출처: 04, 05 변경 제안 1, 답변)
- 블러된 이미지는 어떤 기기인지 알아볼 수 있을 정도로만 흐리게 하고, 누르면 선택이 바뀜 (출처: 05 R2)
- B10 재생/정지와 C03 플레이바는 기본으로 숨기고, 선택된 이미지 안 하단에만 나타남 (출처: 04, 05 변경 제안 2, 답변)
- 재생 중 다른 이미지를 선택하면 소리가 멈춤 (출처: 02, 04)
- 소리 차이는 한 음원에 필터 처리로 구현. 선택한 이미지(PC 스피커 / 5인치 / 8인치)에 맞는 소리가 출력됨 (출처: 01, 02)
  - 방식: Web Audio 저음 필터(고역 통과)로 기기별 저음을 깎음. 기준 주파수 PC 스피커 150Hz / 5인치 60Hz / 8인치 25Hz(거의 원음). 이 값은 시작값이며 들어 보고 조정 (출처: 답변)
  - 재생 시작 0.3초 페이드인, 정지 0.2초 페이드아웃. 플레이바는 실제 재생 위치를 표시 (출처: 06, 답변)
  - 기기를 바꿔 다시 재생하면 멈췄던 위치부터 이어서 재생(같은 구간 비교) (출처: 답변)
- 아무것도 선택하지 않은 상태에서는 마우스 호버 시 이미지가 커서 방향으로 기울어짐(틸트). 선택하면 틸트 없음 (출처: 06, 답변)

### 3-5. S04 모델 선택 구성과 동작
- 섹션 제목: "LOWCORE 모델 비교하기" (출처: 요청)

- 펼친 상태의 모델 이미지 프레임 테두리: S02 선택 이미지와 같은 2px `orchid` (출처: 요청)

## 제작 진행 규칙
AI는 아래 순서대로 한 단계씩만 진행합니다. 단계가 끝나면 결과를 보여 주고 질문 기능으로 '승인 · 다음 단계로 / 수정 요청 / 이 단계 다시 하기'를 묻습니다. 승인 전에는 다음 단계로 넘어가지 않습니다.
1. 목적·범위 확인: 1~2번 항목을 요약해 확인받고, 빠진 정보를 질문합니다.
2. 페이지 설계: 3번 항목대로 페이지와 섹션, 메뉴·버튼 이동만 만듭니다. 색·글꼴·움직임은 넣지 않습니다.
3. 디자인 쌓기: 4번 항목의 컬러, 글꼴, 여백, 반복 요소를 적용합니다.
4. 에셋 삽입: 6번 항목의 로고와 이미지를 넣고, 비어 있는 자리는 어떻게 채울지 묻습니다.
5. 인터랙션: 5번 항목을 바탕으로 동작을 제안하고, 하나씩 승인받아 적용합니다.
6. 반응형: 7번 항목 기준으로 모바일 화면을 점검하고 수정합니다.
7. 배포: 배포 방법을 제안하고, 배포 후 실제 주소에서 확인할 항목을 알려 줍니다.
수정이 생기면 화면과 이 파일을 함께 고칩니다.
