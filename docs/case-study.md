## 2. 기획 의도

- **배경**
  - 방문자의 필요(문서): 소리가 기기마다 달라지는 이유를 이해하고 싶다. 사기 전에 PC 스피커와의 차이를 직접 확인하고 싶다.
  - (초안) 스피커 판매 페이지는 대부분 사양표와 설명 글로 소리를 전달한다. "주파수 응답 35Hz"라는 숫자만으로는 지금 쓰는 PC 스피커와 무엇이 다른지 들리지 않는다.
  - ✏️ 직접 채우기: 직접 들어가 본 스피커·음향기기 사이트 하나와, 거기서 느낀 아쉬움 한 가지
- **목표**
  - 방문자가 PC 스피커와의 저음 차이를 직접 들어 보고, 소리가 달라지는 이유를 이해하도록 돕는다.
  - 전달할 인상: 묵직하고 단단함, 감각적이고 세련됨
  - 피할 방향: 저음 과장·소비자용 느낌 / 자동 재생·갑작스러운 큰 소리 / 구매 강요·과한 할인 강조
- **타깃 사용자 한 줄**: 유튜버·영상 편집자, 홈레코딩 입문 작곡가 — 데스크톱에서 작업하며 PC 스피커를 쓰다가 모니터 스피커를 고민하는 사람
  - (초안) 뒤쪽 "PC 스피커를 쓰다가 모니터 스피커를 고민하는 사람"은 비교 대상을 PC 스피커로 둔 기획에서 이어 쓴 표현이다.
- **배경과 목표의 연결**: (초안) 글로는 전해지지 않는 소리 차이 → 같은 트랙을 기기만 바꿔 들어 보게 한다 → 왜 다른지는 바로 아래 섹션에서 설명한다.

## 3. 핵심 가설

- **가설 설정 배경 한 줄**: (초안) 소리 차이를 확인하고 싶은 사람에게 필요한 것은 설명보다, 같은 조건에서 바로 비교해 보는 경험이라고 봤다.
- **IF-THEN**
  - **IF** (초안) 같은 트랙을 PC 스피커 / LC-5-105 / LC-8-112 중 하나로 골라 재생하고, 기기를 바꿔도 멈췄던 위치부터 이어 들을 수 있는 비교 체험(S02)을 두면
  - **THEN** (초안) 방문자는 PC 스피커와 LOWCORE 모델을 둘 다 재생해 보고, 모델 선택 섹션(S04)까지 내려가 상세 사양을 펼쳐 본다.
- **검증 방향**: (초안) 사용 흐름 테스트 케이스 TC-28(데스크톱)·TC-29(휴대폰)로 "두 기기를 같은 구간으로 번갈아 듣는 흐름을 끝까지 해낼 수 있는가"를 확인한다.
  - ✏️ 직접 채우기: THEN의 실제 행동(두 기기 모두 재생했는지, S04까지 갔는지)을 관찰했다면 그 방법

### 인터랙션 1. S02 비교 체험 — 고르고, 재생하고, 바꿔 듣기

- **무엇을**
  - PC 스피커 / LC-5-105 / LC-8-112 이미지 3개 중 하나를 누르면, 고른 이미지만 오키드 테두리와 확대로 선명해지고 나머지 둘은 흐려진다(흐림 4px + 밝기 0.75).
  - 고른 이미지 안 하단에만 재생 버튼과 플레이바가 나타난다. 재생 버튼을 눌러야 소리가 난다.
  - 재생 중 다른 기기를 고르면 소리가 멈추고, 다시 재생하면 멈췄던 위치부터 이어진다.
  - 아무것도 고르지 않았을 때는 마우스를 올리면 이미지가 커서 방향으로 기운다(최대 약 12°).
- **왜**
  - 핵심 행동인 "같은 트랙을 번갈아 듣기"를 바로 할 수 있게 하려고. 이어 재생은 같은 구간끼리 비교하게 하려고.
  - 선택 = 초점, 비선택 = 블러: 지금 듣는 기기가 무엇인지 화면에서 바로 보이게 한다(R2). 흐린 이미지도 기기를 알아볼 수 있게 밝기를 0.6에서 0.75로 올렸다.
  - 자동 재생 없음, 0.3초 페이드인, 음량 원음의 70%: "자동 재생·갑작스러운 큰 소리" 피하기
- **어떻게**
  - Web Audio 고역 통과 필터로 한 음원(music-sample.mp3)의 저음을 기기별로 깎음. 기준 주파수 PC 스피커 150Hz / LC-5-105 50Hz / LC-8-112 35Hz (두 모델은 사양표의 주파수 응답 시작값과 같게 맞춤)
  - 플레이바는 실제 재생 위치를 표시하고, 누르거나 끌거나 키보드(←→ 5%, Home, End)로 위치를 옮길 수 있다. 누르는 영역 높이 44px
  - 휴대폰(767px 이하)은 이미지가 작아서, 재생 버튼·선택한 모델 이름·플레이바를 이미지 묶음 아래에 넓게 둔다. 자리를 미리 잡아 두어 이미지를 골라도 화면이 밀리지 않는다.

### 인터랙션 2. S04 모델 선택 — 카드에서 상세로 이어지는 펼침

- **무엇을**
  - 모델 카드를 누르면 그 카드가 이미지 프레임으로 커지고, 다른 카드는 화면 끝으로 밀려나 흐려지며, 밀려난 방향으로 상세 사양 칸(12항목)이 펼쳐진다. 0.9초.
  - 흐린 카드를 누르면 좌우가 뒤집히며 그 모델로 바뀌고, 펼친 이미지 프레임을 누르면 거꾸로 접힌다.
  - 상세 칸 맨 아래에 구매(왼쪽)·체험하기(오른쪽). 구매는 '준비 중' 안내창, 체험하기는 S02로 돌아간다.
- **왜**
  - 단계적 공개(R4): 처음에는 이미지·모델명·요약만, 고른 카드에서만 상세 정보와 버튼을 보여 준다.
  - S02와 같은 "선택 = 초점, 비선택 = 블러" 원리를 써서 사이트 전체의 조작 방식을 하나로 맞춘다.
  - 체험하기 버튼: (초안) 사양을 본 뒤 다시 들어 보도록 비교 체험으로 되돌린다.
- **어떻게**
  - 카드가 그 자리·기울기에서 출발해 이미지 프레임 자리·크기로 이어서 변하는 움직임(`src/sections/modelMorph.js`), 곡선 cubic-bezier(0.4, 0, 0.2, 1)
  - 태블릿·휴대폰(1023px 이하)은 가로 펼침에 필요한 1000px 폭이 없어서, 누른 카드 바로 아래로 펼쳐지는 아코디언으로 바꿨다.

### 인터랙션 3. S01 첫 화면 — 문구가 펼쳐지고 체험 버튼이 떠오름

- **무엇을**: 로고 윤곽을 따라 전기 선이 흐르고(Electric Logo), 메인카피·서브카피 네 줄이 위에서부터 한 줄씩 펼쳐지며(Fold Text), 메인카피가 다 펼쳐지면 체험 시작 버튼이 떠오른다. 뒤에서는 보랏빛 고리가 천천히 퍼진다(Magic Rings).
- **왜**: (초안) 첫 화면에서 메인카피를 먼저 읽게 하고, 읽은 직후 체험 시작 버튼으로 시선을 옮기게 하려고. 버튼은 나타나기 전에는 눌리지 않는다.
- **어떻게**: React Bits 컴포넌트 3개(코드 복사 방식, ogl·gsap 사용). 휴대폰·태블릿은 펼침 시간을 줄이고(0.3초 / 0.3초 / 0.8초), 배경 고리는 첫 장면에서 멈춘다. '동작 줄이기'가 켜져 있으면 움직임 없이 바로 표시한다.
